# Цены на Авито из Telegram-канала

Каждое утро (09:41 МСК) GitHub Actions читает прайс поставщика из канала
[t.me/BigSaleApple](https://t.me/BigSaleApple) и ставит цены в ваши объявления на Авито через официальный API.

## Настройка (один раз)

1. **Ключи API Авито.** В личном кабинете Авито → «Для профессионалов» → «Интеграции» / «API»
   получите `client_id` и `client_secret`. В GitHub: репозиторий → Settings → Secrets and variables →
   Actions → **New repository secret** — добавьте `AVITO_CLIENT_ID` и `AVITO_CLIENT_SECRET`.
2. **Подобрать пары.** Actions → «Цены на Авито» → Run workflow → режим `match`.
   Скрипт выгрузит ваши активные объявления и к каждому подберёт позицию прайса —
   получится файл `avito/mapping.csv`.
3. **Проверить пары.** Откройте `avito/mapping.csv` (в Excel или прямо на GitHub).
   Если позиция подобрана верно — впишите `да` в колонку `checked`. Если нет — поставьте
   нужный ключ из колонок `alt_1`/`alt_2` или из `avito/data/prices.csv` (колонка «Ключ») в `source_key`.
   **Цены меняются только у строк с `да`.**
4. **Тестовый прогон.** Run workflow → `sync`. Ничего не меняется — в `avito/data/last_run.md`
   появится отчёт: какие цены стали бы какими.
5. **Включить.** Settings → Secrets and variables → Actions → вкладка Variables →
   New repository variable: `AVITO_APPLY` = `1`. С этого момента цены меняются на самом деле.

Новые объявления: снова запустите `match` — он добавит только новые строки, проверенные не тронет.
Пары с совпадением от 0,85 (`auto_check_score` в конфиге) отмечаются «да» сразу.
`match --rematch` заново подбирает все непроверенные строки.

В названиях объявлений часто нет цвета, поэтому `match` дополнительно берёт первую строку описания
и цвет из последнего файла Автозагрузки аккаунта (API Авито отдаёт его копию). Объявления,
созданные вручную после выключения Автозагрузки, сопоставляются только по названию.

## Правило цены

`avito/config.json`:

| Параметр | Что значит |
|---|---|
| `markup_percent`, `markup_rub` | наценка к цене поставщика: процент и/или рубли |
| `round_to`, `round` | округление: шаг (100 ₽) и направление `up` / `down` / `nearest` |
| `max_change_percent` | если цена меняется сильнее (15%), она не ставится, а попадает в отчёт |
| `max_price_age_days` | посты с датой прайса старше стольких дней не используются |
| `min_items_ratio` | если позиций в прайсе меньше 60% от прошлого раза — ничего не менять |

Своё правило для отдельного объявления — колонка `rule` в `mapping.csv`:
`+2000`, `+5%`, `-500`, `=45000` (фиксированная цена) или `нет` (не трогать).

## Как читается прайс

Канал публичный, его веб-версия `t.me/s/BigSaleApple` открывается без входа в Telegram.
Скрипт разбирает строки вида `🇮🇳 S26 12/256GB Black — 60100`; эмодзи и флаги отбрасываются,
пометка после цены («(Snapdragon, без esim)», «(Дефект коробки)») считается частью названия —
это другой товар. Если одна позиция есть с разными флагами, берётся самая дешёвая.
Строки без цены («— 🚗», в пути) пропускаются — такие объявления остаются с прежней ценой.

Прайсы в картинках (например, iPhone) скрипт не читает — только текст.

## Вручную

```bash
python3 avito/tools/avito_prices.py prices        # прайс → avito/data/prices.csv
AVITO_CLIENT_ID=… AVITO_CLIENT_SECRET=… python3 avito/tools/avito_prices.py match
AVITO_CLIENT_ID=… AVITO_CLIENT_SECRET=… python3 avito/tools/avito_prices.py sync          # тест
AVITO_CLIENT_ID=… AVITO_CLIENT_SECRET=… python3 avito/tools/avito_prices.py sync --apply  # по-настоящему
```

Если объявления загружаются через Автозагрузку Авито, следующая выгрузка фида вернёт цену из фида —
тогда цены нужно менять в фиде, а не через API.
